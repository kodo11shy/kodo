## 4. 今日变更记录

### 2026-06-29-001：首页/封面设计复盘与 Claude Code 反思要求

完成内容：
- 读取远程 main 最新提交，确认 2026-06-28 存在多次连续首页/封面设计改版提交。
- 检查最新首页实现文件：
  - `miniprogram/pages/index/index.wxml`
  - `miniprogram/pages/index/index.wxss`
  - `miniprogram/pages/index/index.js`
  - `miniprogram/app.wxss`
  - `miniprogram/pages/teacher/dashboard/dashboard.wxml`
  - `miniprogram/pages/teacher/dashboard/dashboard.wxss`
- 对比 6 月 25 日原“家长信任型首页”结构与 6 月 28 日最终“单屏完整封面”结构。

检查结论：
- 问题不在于“封面很难做”，而在于设计流程没有守住产品验收清单。
- `/frontend-design` 更像给出了视觉方向或局部改版能力，不等于能自动完成一个真实小程序的产品级首页。
- Claude Code 后续多次提交显示方向在反复试错：从暖色、紧凑、单屏、通知上图，到最终压缩为一屏封面；但没有看到明确的“必须保留信息清单”和“真机验收截图”闭环。
- 最终首页把很多对家长首次理解很关键的信息弱化或移除了：
  - 联系方式只显示“微信/电话”标签，不直接显示微信号或电话号码。
  - 收费说明没有展示，虽然 JS 仍读取 `feeStandard`。
  - “精彩瞬间”标题被拿掉，只剩一个 170rpx 高的紧凑轮播，存在感弱。
  - “关于托班”的说明被压缩成一句话，缺少信任建立。
  - 老师入口弱化是对的，但家长端首屏也被压缩得过于工具化。
- “一屏完整封面”这个目标本身有偏差：托班首页不是广告海报，也不是只看一张封面图；它需要让家长快速确认机构、联系方式、通知、孩子内容、收费/服务信息。
- 全局暖杏/米色令牌会让老师端、家长端、公共首页都变成同一类暖色，容易形成单一色调，降低业务角色区分。
- 首页 `previewPhoto` 现在使用 `item.url`，而 `item.url` 优先来自 `thumbnail`；如果存在缩略图，点击预览可能打开缩略图，不符合“列表缩略图、预览原图”的性能设计。
- 首页 `.quick-bar` 对家长入口前的分隔线没有完全按联系方式存在与否控制，存在边界布局瑕疵风险。
- 老师工作台新版结构比首页更接近可用产品，但 CSS 内联 data URI 图标较多，维护性不如统一图标资产/组件。

原因分析：
- 设计任务没有先冻结“不可丢失的信息”：机构名、真实照片/品牌、最新通知、联系方式具体值、家长入口、精彩瞬间、收费说明、老师入口弱化。
- 插件产出可能偏“视觉稿”，但真实小程序还需要信息架构、业务约束、数据字段、真机尺寸、安全区、微信组件限制一起验收。
- 多次连续提交说明缺少参考标尺。教育/托管/幼儿园/课后服务类首页通常不是把所有东西塞进一屏，而是优先展示：真实场景图 + 机构名 + 联系/咨询入口 + 最新通知 + 照片/活动 + 服务/收费说明。
- 把“好看”理解成“换暖色和压缩排版”，导致内容清楚度下降。

建议结论：
- 不建议在 `465c4a9` 上继续微调。应先让 Claude Code 做一次完整复盘，提出 2-3 个首页方案后再改。
- 首页方向应回到“家长信任型入口”，而不是“单屏海报型封面”。
- 可以保留真实照片大图、通知浮层、老师入口弱化这些方向，但必须恢复/明确展示联系方式、精彩瞬间标题、收费/服务信息。
- 首页轮播建议列表显示缩略图，点击预览原图，需要在数据结构中同时保留 `thumbnail_url` 和 `url`。
